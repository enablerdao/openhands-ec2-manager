## 計画中の新アーキテクチャ（分離型）

新しいアーキテクチャでは、フロントエンドとAPIサーバーを分離し、OpenHandsインスタンスを個別のEC2インスタンスとして起動・管理します。

### 1. 分離型アーキテクチャ

```
                                  +-------------------+
                                  |                   |
                                  |  Route 53 (DNS)   |
                                  |                   |
                                  +--------+----------+
                                           |
                                           | DNS解決
                                           v
+------------------+            +----------+-----------+
|                  |            |                      |
|  ブラウザ        +----------->+  フロントエンドサーバー |
|                  |            |  (/client)           |
+------------------+            |                      |
                                +----------+-----------+
                                           |
                                           | 内部API呼び出し
                                           v
                                +----------+-----------+
                                |                      |
                                |  APIサーバー          |
                                |  (/server)           |
                                |                      |
                                +----------+-----------+
                                           |
                                           | AWS SDK
                                           v
                                +----------+-----------+
                                |                      |
                                |  AWS EC2             |
                                |  (インスタンス管理)    |
                                |                      |
                                +----------+-----------+
                                           |
                                           | 起動・管理
                                           v
                      +----------+   +-----+------+   +----------+
                      |          |   |            |   |          |
                      | OpenHands |   | OpenHands  |   | OpenHands |
                      | インスタンス1 |   | インスタンス2 |   | インスタンス3 |
                      |          |   |            |   |          |
                      +----------+   +------------+   +----------+
```

### 2. プライベートネットワーク + リバースプロキシ構成

セキュリティを強化するため、OpenHandsインスタンスをプライベートサブネットに配置し、リバースプロキシを通じてアクセスする構成も検討中です。

```
                                  +-------------------+
                                  |                   |
                                  |  Route 53 (DNS)   |
                                  |  *.teai.io        |
                                  +--------+----------+
                                           |
                                           | DNS解決
                                           v
+------------------+            +----------+-----------+
|                  |            |                      |
|  ブラウザ        +----------->+  リバースプロキシ     |
|  user1.teai.io   |            |  (Nginx)            |
+------------------+            |                      |
                                +----------+-----------+
                                           |
                                           | 認証 & ルーティング
                                           v
                      +------------------------------------------+
                      |            VPC プライベートネットワーク     |
                      |                                          |
                      |  +----------+   +------------+           |
                      |  |          |   |            |           |
                      |  | OpenHands|   | OpenHands  |           |
                      |  | user1    |   | user2      |           |
                      |  | 10.0.1.5 |   | 10.0.1.6   |           |
                      |  +----------+   +------------+           |
                      |                                          |
                      |         +-------------------+            |
                      |         |                   |            |
                      |         | フロントエンド/API  |            |
                      |         | 管理サーバー        |            |
                      |         |                   |            |
                      |         +-------------------+            |
                      |                                          |
                      +------------------------------------------+
```

## 通信フロー（プライベートネットワーク + リバースプロキシ構成）

1. ユーザーがブラウザで `user1.teai.io` にアクセス
2. DNSがこのサブドメインをリバースプロキシサーバーのIPに解決
3. リバースプロキシがユーザー認証を確認
4. 認証が成功すると、リバースプロキシがリクエストを対応するOpenHandsインスタンス（例: 10.0.1.5:3000）に転送
5. OpenHandsインスタンスがレスポンスを返し、リバースプロキシを経由してユーザーに届く

## セキュリティ上の利点

この新しいアーキテクチャには以下のセキュリティ上の利点があります：

1. **インスタンス分離**: 各ユーザーは独自のOpenHandsインスタンスを持ち、他のユーザーと分離されています
2. **ネットワーク分離**: OpenHandsインスタンスはパブリックインターネットから直接アクセスできません
3. **認証の一元化**: リバースプロキシで認証を一元管理できます
4. **アクセス制御**: サブドメインとユーザーの対応関係を管理し、適切なアクセス制御を実現できます

## ポート転送設定

現在のNginx設定では、以下のポート転送が設定されています：

- ポート80 → ポート3000（メインアプリケーション）
- WebSocket接続（/socket.io/）→ ポート3000
- /port43967/ → ポート43967（補助サービス）

これらの設定は、新しいアーキテクチャでも維持され、各OpenHandsインスタンスに適用されます。
